# GM 補答紀錄 — 2026-09-14 Character Creation

本檔記錄本輪自動創角壓測中，GM／系統設計者對創角流程、技能稀有度、語言、施法者、角色背景與自動 build 行為的明確補答。

來源性質：

- `[D100_CANON]`：已存在於上游 Sheet／角色卡證據，這裡只記交叉確認方向。
- `[GM_PROVISIONAL]`：GM 已明確指定目前 D100 創角應如何理解／操作。
- `[SRD_BRIDGE]`：D&D 3.5 只作職業文化／缺漏偵測參考，不直接升格為 D100 規則。
- `[OPEN_QUESTION]`：壓測發現但尚未有足夠來源可安全補完的細節。

---

## 1. 自動創角的起始模板 `[GM_PROVISIONAL + D100_CANON support]`

若沒有另行指定，自動創角優先使用：

```text
基準起始 CP：200
三件常規起始魔法物品：+3 / +4 / +5
```

這與上游 Sheet 的 200 CP 常規配置一致。

注意：200 是**基準起始 CP**，仍須依九大屬性 adjustment 總和相對於 10 進行增減；不是所有角色最後都固定 200 CP。

玩家／DM 明示其他起始 CP 或物品配置時，以明示配置優先。

---

## 2. 語言 `[GM_PROVISIONAL]`

### 2.1 免費通用語

創角時角色取得：

```text
通用語 Lv3
```

不消耗 CP。

### 2.2 施法者文化／教育門檻

施法者創角至少需具備：

```text
任一難度2語言 Lv1 或以上
```

來源可以是：

- 種族贈送；
- 背景／模板贈送；
- 其他合法免費來源；
- 花 CP 購買。

若種族等來源已經給予難度2語言，就**不需要**為施法者身分再購買另一門難度2語言。

### 2.3 基本職業模板只是推薦，不是固定語言稅

3.5 的 class-related language 可作自動創角基本模板，例如：

```text
法師：龍語
牧師：天界語／深淵語／煉獄語之一
德魯伊：德魯伊語（另可參考森林語／Sylvan 的文化脈絡）
```

但 D100 變體 build 的真正門檻是：**至少一門難度2語言 Lv1**。

因此法師不必永遠是龍語，牧師也不必永遠是天界語。

---

## 3. 技能稀有度有兩條互相獨立的軸 `[GM_PROVISIONAL]`

### 技能等級稀有度

```text
Lv1–3：正常創角自由範圍
Lv4+：極為稀有／罕例，需要可信服背景與審查
```

不得把 `Lv4+ 稀有` 誤讀成 `Lv3 也最好不要買`。

### 技能難度稀有度

```text
難度1–2：正常創角自由範圍
難度3+：能力本身已屬稀有／特殊，需要可信服背景與審查
```

即使只是難度3技能 Lv1，也應產生 review flag。

`review flag` 不是禁止購買；它表示需要回答「角色為何會這項能力」。

---

## 4. 前置能力在購買當下就必須成立 `[GM_PROVISIONAL + D100_CANON support]`

若能力條文寫有：

- 其他技能／專長；
- 最低技能等級；
- 屬性門檻；
- 施法環數；
- 職業／領域／種族等條件；

則購買該能力時必須已經滿足。

不能「先買後補前置」。

自動創角應使用 prerequisite graph 驗證，而不是只檢查 CP 是否足夠。

---

## 5. 施法環數允許非同步預購核心技能 `[GM_PROVISIONAL]`

施法核心技能**不要求始終同級**。

角色可以先投資下一環的一部分核心技能，但在所有必要核心技能都達到該等級前，不能施展該環法術。

操作上：

```text
可用法術環數 = 該施法體系所有必要核心技能等級的最低值
```

例如法師：

```text
奧術知識3
黑魔導3
黑魔力2
→ 仍為二環法師
```

第三環的兩項技能代表「已在學下一環」，不是非法 build。

---

## 6. 高環施法者的世界尺度 `[GM_PROVISIONAL + D100_CANON context]`

- 三環已屬初始角色中的頂尖／菁英施法者；在一般費倫式世界尺度中已不是普通新手。
- 三環創角應有可信服的年齡、教育、師承、教會、血脈或長期實踐背景。
- 四環以上更應主動產生強 review flag；不能只因屬性高、CP 足就自動買上去。

上游 `施法者創角須知` 的年齡表是假設「約四歲開始法術啟蒙、成長過程無外在變因」的理想／最快進程參考；自動創角不能把它誤讀成所有施法者都從四歲受訓。

---

## 7. 法師學派 `[GM_PROVISIONAL]`

D100 不強制法師選學派。

```text
通才法師：合法
學派專精：可選 build
```

自動創角應提供「法師學派／通才」的推薦選項，但不得自動把推薦變成必修。

若 `學派專精` 本身有難度、環數或其他前置，仍照能力條文驗證；角色可以先有 RP 上的學派傾向，等達前置後再正式購買。

---

## 8. 牧師的信仰與領域 `[GM_PROVISIONAL]`

牧師不是只買 `宗教知識 + 神術` 就完成。

玩家繳交牧師角卡時至少要明示：

```text
真正信仰的神祇／宗教
領域
```

領域必須與神祇／信仰一致。

領域相關技能／能力是否額外購買仍依各能力條文；但「牧師有真實信仰與領域身分」本身是角色身分義務，不應因自由 CP 制消失。

---

## 9. CP 可以保留，不要求創角花完 `[GM_PROVISIONAL]`

角色可以：

- 購買技能／專長；
- 補 HP / SP；
- 在有正式規則時補其他基礎數值；
- 保留 CP 供日後學習／成長／重骰。

**不要求創角一定花完全部 CP。**

但自動創角不得因為「可以存」就提前停止搜尋。大量剩餘 CP 應先經過完整候選掃描與反事實 build pass，確認不是 generator 偷懶。

`[OPEN_QUESTION]`：GM 已指出 CP 亦可用來填補基礎數值缺口，但目前尚未定位到可安全採用的「CP → raw/basic stat」正式換算公式；在找到來源前不要自創。

---

## 10. 創角獎勵 HP/SP 的順序 `[D100_CANON + GM_PROVISIONAL workflow]`

正確流程：

```text
完成技能／專長配置
→ 統計近戰相關 CP／法術相關 CP
→ 依門檻取得並擲獎勵 HP/SP
→ 算基礎 HP/SP
→ 再決定是否用 CP 額外購買 HP/SP
```

不能先擲獎勵，再大幅修改 build 後沿用舊骰。

`[OPEN_QUESTION]`：哪些技能／專長精確計入「近戰相關 CP」或「法術相關 CP」目前沒有完整分類表。角色卡證據顯示這兩個 qualifying investment ledger 與總技能 CP 是分開維護的，因此不能簡單把所有戰鬥分類技能／所有施法者持有技能全部硬算進去。

## 11. 創角審核四類 `[GM_PROVISIONAL]`

### A. 自動創角時必填

機器可客觀驗證、缺少就不能完成 build 的項目，例如：

- 起始配置與 CP；
- 種族、九大屬性與 derived values；
- 免費通用語 Lv3；
- 施法者至少一門難度2語言 Lv1；
- prerequisite graph；
- 可用施法環數；
- CP 不超支；
- 獎勵 HP/SP 與基礎 HP/SP 計算。

### B. 玩家繳交角卡時必填

不能由系統替玩家決定、但角色身分本身要求明示的內容，例如：

- 牧師神祇／信仰與領域；
- 需要誓約／教團／傳承的角色身分；
- 高環施法者的訓練／師承／年齡背景等。

### C. 玩家繳交角卡時存疑

數學可合法，但需要背景解釋的內容，例如：

- Lv4+；
- 難度3+；
- 高環／世界尺度稀有能力；
- 能力組合與申報背景明顯不相稱。

存疑 ≠ 禁止。

### D. 自動創角自由 build

在規則合法且沒有稀有旗標的範圍內自由配置，例如：

- 難度1–2、Lv1–3；
- HP/SP 投資；
- 額外語言；
- 生活／工作／社交／知識／興趣技能；
- 合法的下一環核心技能預購；
- 法師學派方向推薦；
- 保留 CP。

---

## 12. 3.5 的用途：缺漏偵測器，不是第二套創角規則 `[SRD_BRIDGE]`

可拿 3.5 的：

- class-related bonus languages；
- automatic class features；
- class skill 分布；
- code / oath / deity / druidic tradition 等職業文化結構；

來問：

> D100 從 class chassis 改成自由 CP 後，有沒有把某個「角色本來應該知道／具備／交代」的資訊漏掉？

但不得直接推出：

```text
3.5 class skill = D100 必修技能
```

3.5 class skill 只是一級職業文化線索；真正硬規則仍需 D100／GM 支持。

---

## 13. 本輪自動創角 failure `[TEST_EVIDENCE]`

本輪五名自動角色普遍保留 38%～75% 可用 CP。經反查，D100 並非缺乏合法可買能力；主要 failure 是：

1. generator 把 `Lv4+ 稀有` 過度收縮成 `Lv3 也少買`；
2. 只驗證已想到的技能，沒有廣泛枚舉候選；
3. 背景沒有真正轉化為生活／工作能力候選；
4. 拿「可以存 CP」當作提前停止搜尋的理由；
5. 低屬性角色取得的補償 CP 沒有被有效用於橫向能力／HP/SP／未來規劃。

因此後續修正應放在 Character Builder pipeline 與模塊調度，不應靠降低稀有門檻解決。
