# D100 裁定 Regression Cases

這些不是固定劇本，而是拿來測 GPT 是否真的在使用 D100，而不是偷套其他系統。

每次更換模型、改 DM 指令或大改 core rules 後，可以拿這些案例做 smoke test。

---

## Test 1 — 寶箱飛箭機關

### 情境

A 寶箱內有飛箭機關。PC 搜索失敗，沒有發現機關，直接開箱。

### DM 應做

1. 不因搜索失敗就宣布箭矢自動命中。
2. 開箱後觸發機關。
3. 依陷阱設計選擇合理接口：
   - 單一飛箭：陷阱攻擊 vs 閃避 `[DM_DEFAULT]`
   - 面狀箭雨／爆發：可改用抗噴吐
4. 若箭頭帶毒，命中後再進抗毒素。
5. 若公開說「抗毒素」會提前洩漏箭有毒，可等接觸／症狀揭露後處理或暗擲。

### 不應做

- 自動命中，理由只是「你沒找到陷阱」。
- 直接使用 D&D Reflex save 數值。
- 把抗噴吐與閃避無差別混用。

## Test 2 — 舊日支配者之血眷屬化

### 情境

具有眷屬化權能的古神血液碰到 PC。

### DM 應先問效果機制

若真正作用是：

```text
血液作為媒介 → 改寫角色形態／物種／存在狀態
```

主要防禦：

```text
抗轉化
```

若另有真正獨立的生理毒害：

```text
毒害階段 → 抗毒素
轉化階段 → 抗轉化
```

若轉化完成後又有強制服從：

```text
控制階段 → 抗控制
```

### 不應做

只因為「血」就一律用抗毒素；也不應一次叫玩家連骰抗毒、抗轉、抗控、精神、靈魂，除非能力真的有五個不同因果階段。

## Test 3 — 奪心魔抽魂

### 情境

某奪心魔能力不是單純腦控，而是把 PC 的靈魂拉離身體。

### 主要接口

```text
靈魂 = SPI×5
```

若能力是一股主動力量，可設：

```text
奪魂值 vs PC 靈魂
```

做對抗。

### 後果

來源 core 尚沒有「靈魂判定失敗統一狀態」。因此能力條目應自己寫：

- 失敗一次的效果
- 多次失敗是否累積
- 抽離完成條件
- 是否可被中斷／救回

這些不能由 GPT 假裝已有正典。

### 不應做

把所有心靈相關效果都丟給抗控制。若效果真的抽魂，優先是靈魂。

## Test 4 — 奈瑟瑞爾古魔法書

### 情境

PC 閱讀非常古老的魔法書。

### 正確分層

如果只想看懂文字：

```text
文書解讀
```

如果要理解其中奧術歷史／理論：

```text
奧術知識
```

如果文字／書頁本身正在運行法術結構：

```text
辨識法術
```

如果它作為特殊魔法物品具有異常結構：

```text
魔法物品學
```

### 若書有精神灌注 + 轉化

合理多階段：

```text
閱讀／理解
→ 精神灌注：精神
→ 只有灌注真正建立模板後
→ 轉化：抗轉化
```

### 不應做

- 看見「古魔法書」就自動叫 SAN check。
- 一次奧術知識成功就揭露全部神器權能。
- 因為來源是魔法就無條件額外加一道抗魔法。

## Test 5 — 直視希瑞克化身

### 情境

PC 主動直視希瑞克化身。

### 若效果是神性／認知衝擊

```text
精神
```

因為問題是：

> 心智能否承受所見／所理解的存在？

### 若化身接著下達超自然命令

```text
抗控制
```

### 若直接觸碰／奪取靈魂

```text
靈魂
```

### 不應做

把「看見神祇」與「被神祇控制」當成同一件事。

## Test 6 — 樸素神器書與位面級魔法背景

### 情境

一本外觀極樸素的神器古書，其魔法效應不是局部放射，而是與整個物質位面共延展。

若該團採用 3.5 artifact aura bridge，artifact 可具有 Overwhelming aura；但：

```text
Overwhelming = 強度
```

不自動等於：

```text
位面級範圍
```

位面級範圍必須是神器自身條目。

### 探測結果 `[DM_DEFAULT]`

如果整個位面都處於相同背景：

```text
偵測存在：成功
定位書本：未必成功
分類背景：可能成功
從局部差分找源頭：可能做不到
```

DM 不應說「神器因為太強所以 detect magic 看不到」；也不應說「偵測到 Overwhelming，所以立刻知道這本書就是源頭」。

## Test 7 — 高階角色的 Action Economy 不能被壓扁

### 情境

高階 PC 進入正式戰鬥。角色卡同時具有：

- 一般動作；
- 每輪自由動作；
- `法術瞬唱`；
- `即刻備戰／及時備戰`；
- `一心二用`；
- 可啟動魔法物品；
- 受擊／敵方施法／距離改變等觸發能力；
- 開戰前已存在的 buff。

例如某角色有：

```text
即刻備戰 Lv3
一心二用 Lv1
可啟動魔法物品
```

另一名施法者有：

```text
法術瞬唱
一般施法
自由動作
```

### DM 應做

進戰前先從角色卡建立 Action Palette，逐輪維持 Action Ledger，而不是只記一個 `declared_action`。

每輪至少知道：

```text
一般動作是否已用
自由動作還剩幾次
哪些即時動作仍可用
法術瞬唱是可用／已保留／已用
一心二用是否仍可嘗試
哪些魔法物品可啟動
哪些 trigger 正在等待事件
```

`一心二用` 的來源效果：

```text
同一行動中進行兩個不互相排斥的動作
檢定 = 感知 + 技能等級×10
```

`即刻備戰／及時備戰` 的來源效果必須真的改變時間窗口：喝藥、抽武器、使用魔法物品等自由動作可轉為即時動作。

`法術瞬唱` 也不是「把一般法術變快但仍只做一件事」；同一輪仍可保有另一個一般動作，並可依戰鬥流程保留瞬唱使用權到適當時點插入。

### 真玩家、NPC mode、PL+PC mode 要分開

真玩家控制 PC：

- DM 不替玩家自動燒瞬唱、藥水、物品或每日能力。
- 但 DM 不得直接跳過合法反應窗口；必要時簡短確認玩家是否要插入。

四聲部／GPT 在 `npc` mode：

- 可以把角色當成熟悉自己能力的 autonomous actor。
- 應合理考慮瞬唱、自由、即時、物品、一心二用、trigger 的組合。
- 這些行動仍是 NPC／actor pipeline 行動，不得事後聲稱是「Player choice」。

四聲部／GPT 在明確 `pl_pc` mode：

- 必須先有 Player Voice decision。
- Player Voice 可故意採取非最佳但有趣的選擇。
- 再由 PC layer 翻譯成角色宣告／扮演。

### 不應做

- 一個角色用完一般動作後直接宣布「本輪結束」，忽略尚未使用的自由／即時／瞬唱權。
- 只讀攻擊、閃避、HP，而不讀技能、裝備啟動、被動與當前 buff。
- 因為 Boss 很強而偷偷不給玩家使用原本合法的反應窗口。
- NPC mode 的四聲部行動被事後解讀成「玩家偏好」。
- PL+PC mode 仍由 DM 直接替四聲部 PC 做關鍵決策。

## Test 8 — Alignment 不是行動腳本

### 情境

某 PC / NPC 為：

```text
alignment: Chaotic Evil
presented_persona: helpful, polite
current_affect: calm
```

他正在救一名受傷陌生人，而且過去數日都表現得相當友善。

### 分析師應做

可以把以下張力當分析素材：

```text
alignment
vs presented persona
vs current affect
vs actual behavior
vs roles / obligations / relationship position
```

並提出可撤回解讀，例如：

- 善行可能是形象、依附、策略、義務或真正價值變動；
- 長期行為若真的改變，可以建議觀察 alignment 是否需由玩家／GM 顯式轉變。

### 不應做

- 因為 CE，就要求角色現在必須傷害傷者。
- 因為角色做了善事，就自動把 alignment 改成 Neutral 或 Good。
- 要玩家擲骰「能不能演得像 CE」。
- 把分析師的其中一個解讀寫成角色真正內心。

## Test 9 — 四聲部 PL+PC 必須存在真正 Player Layer

### 情境

四聲部控制四名角色。

Case A：DM 未特別要求 PL+PC。

```yaml
four_voice_control:
  mode: npc
```

Case B：DM 明確說「四聲部現在作為玩家＋PC 一起跑」。

```yaml
four_voice_control:
  mode: pl_pc
```

### Case A 應做

四聲部可直接作為高品質 autonomous NPC 行動。

但不得從其行動事後發明：

> 「赫茲玩家偏好冒險」

除非真的存在 Player Layer evidence。

### Case B 應做

至少保留：

```text
Player Voice
→ agenda / interpretation / decision
→ PC declaration
→ DM resolution
```

例如玩家 voice 可以說：

> 「我知道艾斯特理性上應該撤，但我想讓他因好奇心多看一眼。」

PC 才再把這個選擇演出。

### 不應做

- 直接由 DM 讓四名 PC 自動做最合理選擇。
- DM 演完 PC 再反推「玩家就是這個 playstyle」。
- 讀心者 hypothesis 取代 Player Voice decision。

## Test 10 — 秘密必須在檢定前存在

### 情境

酒館內有一名不起眼男子。PC 故意談到「失蹤抄寫員」與「40gp 文件箱」，並觀察誰有反應。

### 正確順序

在男子第一次產生可被觀察的特殊反應之前，至少 committed：

```text
identity floor
relevant knowledge / belief
為何該詞會引發反應
current goal / constraint
原本下一步要去哪裡（若會影響尾隨）
與事件是否真的有關
```

之後才：

```text
PC 察言觀色
→ 成功／失敗
→ 決定 PC 發現多少
```

如果 PC 再尾隨：

```text
男子原本要去哪裡已先存在
→ 尾隨檢定只決定是否跟住／被發現／能看到多少
```

### 不應做

- 察言觀色成功後才決定「好，那他其實是學院間諜」。
- 尾隨失敗後才決定「其實他只是普通書記」。
- 玩家猜中後臨時改真相，因為「太容易被猜到」。
- 玩家猜錯後直接迎合其理論，讓世界變成那樣。

### 允許

沒有因果負擔的 surface detail 可以之後生成，例如：

- 路上某家店名；
- 不重要的衣服顏色；
- 巷道裝飾。

前提是不反向改寫已 committed 的真相核心。

# Regression 判準

一個合格的 D100 DM 模型應該穩定做到：

- 五抗與三特殊判定不混成一池。
- 判定看效果性質，不只看來源標籤。
- 不濫加多重 saving throws。
- 知道搜索、偵察、文書解讀、辨識法術、魔法物品學是不同資訊層。
- 知道 D100 一輪 = 1 秒。
- 不自動使用 CoC SAN。
- 不自動使用 3.5 Fort/Ref/Will。
- 不把高技能當成能創造不存在的感官資訊。
- 規則缺漏時標記 open/default，而不是編造原文。
- 戰鬥中把角色卡視為 Action Palette，而不是每輪一個動作的數值表。
- 不跳過自由動作、即時動作、法術瞬唱、一心二用與觸發式能力的合法窗口。
- Alignment 是分析座標，不是行動腳本。
- Relationship fact、Actor belief、Analyst interpretation、Politician forecast 分層。
- 四聲部 NPC mode 與 PL+PC mode 行為路徑不同。
- PL+PC mode 不跳過 Player Layer。
- hidden truth 在第一次可觀察／可影響前 committed。
- Causal Graph 與 Evidence Graph 分離；骰子改變發現與後果，不反向決定世界原本是什麼。
